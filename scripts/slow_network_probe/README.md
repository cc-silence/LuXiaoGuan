# 慢网络验证：中文使用说明

## 拿到免安装测试包后这样用

1. 把 ZIP 压缩包拷到那台需要测试直连的 Windows 64 位电脑。
2. **先全部解压**，不要只复制 EXE，也不要在压缩包里直接运行。
3. 双击 **开始直连测试.exe**，工具会自动开始，不用安装 Python，也不用输入命令。
4. 等几分钟。它会检查软件更新和两类离线依赖，先读取文件首段；连通后才完整下载并校验，可能使用几百 MB 流量。
5. 测试结束会打开“测试报告”文件夹，把本次生成的 **ZIP 报告**发回来即可。里面同时有中文结果和供分析使用的详细记录。

工具全程测试直连，不走软件或系统代理，不会安装更新、安装依赖或操作路由器。按 Ctrl+C 可取消并保留已完成的报告。下载的临时文件会清理，不记录内测码或代理密码。

在线检查失败时，工具仍可用随包已验签地址继续测试文件下载。报告会明确标注随包地址，不会把它算成在线检查成功或当前最新版本。

如果程序目录无法保存报告，会自动改存到用户主目录的 LuXiaoGuan_NetworkReports 文件夹；结束时会显示实际位置。

以下是源码运行说明，使用上面的免安装包时不用看，也不用输入下面的命令。

## 你这台电脑怎么用

1. 打开 PowerShell（Windows 的命令窗口）。
2. 先复制下面这一行，按回车，进入源码目录：

```powershell
cd "C:\Users\CC\Desktop\Work\RouterManager\RouterManager_python"
```

3. 再复制下面这一行，按回车，先测不走代理的直连：

```powershell
python -m scripts.slow_network_probe.runner --route direct --sample-only
```

这一轮检查软件更新、常用依赖和抓包依赖，并尝试读取下载文件的前 64 KB，不会下载整个大压缩包。它会分别使用原来的等待时间和较长等待时间进行对比。网络不通时可能需要等几分钟，整个测试包含多项请求，不是整轮只等 180 秒。

窗口还没回到可以输入命令的状态，就表示仍在运行。要提前停止，按 Ctrl+C；已经得到的报告会保留。

## 报告在哪里

报告保存在源码目录下的：

```text
build\network-probes
```

文件名包含运行时间和线路名称，扩展名是 .json。这是记录测试结果的文本文件，你不用自己分析英文内容，把本轮生成的文件交给我分析即可。

程序结束时，窗口最后一行也会显示具体报告路径。报告不记录内测码或代理密码。

## 再测软件里配置的 HTTP 代理

先在软件的代理设置里启用并保存正确的 HTTP 代理，然后在同一个 PowerShell 窗口运行：

```powershell
python -m scripts.slow_network_probe.runner --route http_proxy --sample-only
```

直连和代理应在同一台电脑、同一个网络下先后测试，方便比较。这个命令不会自行换成直连；如果该代理未配置或未启用，会直接提示错误。

如果你配置的是 SOCKS 代理，把命令里的 http_proxy 换成 socks_proxy；系统代理则换成 system_proxy。

## 什么时候测完整下载

先看上面的首段测试。如果还要验证完整文件，运行下面这一行：

```powershell
python -m scripts.slow_network_probe.runner --route direct
```

测代理的完整下载，则运行：

```powershell
python -m scripts.slow_network_probe.runner --route http_proxy
```

工具只有在延长等待后的首段读取成功后，才会完整下载该文件，并核对文件指纹，也就是检查下载内容是否完整、有没有损坏。测试文件用完自动删除，不会安装更新或依赖，也不会操作路由器。

完整下载可能接收几百 MB 数据，耗时会更长；每个完整文件最多等待 15 分钟。每轮完整下载总额度为 1 GiB。增量更新只选一个有签名目录记录的最大压缩文件作代表，不会逐个下载所有增量文件。

## 直连检查失败，怎样继续测下载地址

如果直连拿不到更新清单，工具就不知道本次应该下载哪个文件，会记录“跳过”，不能把它当成下载成功。

如果本机有可用代理，可以使用：

```powershell
python -m scripts.slow_network_probe.runner --route direct --discover-via-proxy --sample-only
```

这个命令先尝试直连；只有拿不到清单时，才通过已配置的第一个代理取得并验证下载地址，然后仍通过直连测试那些文件。报告会分开记录代理取得地址和直连下载，代理成功不会算成直连成功。

## 如何理解结果

- 原来失败、延长等待后成功：说明等待时间可能确实影响结果，再根据客户电脑的实测决定是否调整软件。
- 两次都在收到文件数据前失败：继续查线路、域名、加密连接或浏览器与软件的网络差异，不能认定只要加长等待就能解决。
- 收到了一部分数据后失败：属于传输中断，需要看具体阶段和耗时。
- 文件指纹不一致：完整性校验失败，不能作为可安装文件使用。
- “跳过”：前置清单没拿到或超过本轮下载额度，不代表通过。

客户网络的结论必须在客户电脑上测试。本机成功或失败，都不能代替客户的结果。

## 等待时间和边界

较长等待方案允许建立连接最多 45 秒、连续无数据最多 60 秒；单次更新检查中的清单和目录共享最多 180 秒。依赖清单检查也有 180 秒上限。底层网络可能提前报错，所以设置了 45 秒不代表一定会等满 45 秒。

更新检查使用和软件一致的 Qt 联网引擎；增量文件和离线包使用和软件一致的 Requests 联网库。每次探测新建连接，与软件复用连接的情况会有差异。原有参数按单条线路隔离比较，不完全复现软件多条线路轮流尝试的过程。完整软件 ZIP 在界面中交给浏览器处理，这里用下载探针验证文件，并不模拟浏览器本身。

工具不修改正式版默认参数、Cloudflare 地址、软件设置或路由器。仍会验证证书、清单签名和文件完整性。取消、超时和失败后会回收诊断进程及临时文件。

目前在 Windows 上验证，读取的是普通客户端已保存的内测码；没有发布者凭据选项。没有验证 Debian 下运行。
