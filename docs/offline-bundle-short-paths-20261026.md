# 离线包短目录与旧格式兼容核查（2026-10-26）

## 修改结果
- 新资源的版本目录采用本机下载日期加序号，例如 versions/20261026-01。日期只用于命名；完整 SHA-256 仍保存在 revision.json 和已签名清单中。
- 同一天不同资源分配不同序号；同一资源重试时复用既有目录。用户自建的同名目录不覆盖。完整身份不再从文件夹名称推断。
- 对象文件仍保留完整指纹名，云端 ZIP、签名、清单及包内结构不变。原示例的对象相对路径从 189 字符变为 136 字符，减少 53 字符；序号超过两位时目录稍长。
- 新版可以原位读取旧64位目录，无需重新下载或强制迁移。此前用户已确认兼容方向：旧版未升级程序不支持新日期目录，需要升级后读取。
- 下载、安装、提取、版本比较、下载完成后的目录回显及清理统一接入公共布局层。主线程直接使用后台返回的目录名，不扫描目录。
- 未直接迁移、重命名或删除用户当前离线资源；仅在临时测试目录验证。现有旧包继续原位使用，后续新版本资源下载使用短目录。未重新打包或发布。

## 旧清理功能
新版同时识别旧64位目录、新日期目录和旧 ZIP。旧目录不要求存在新版 revision.json。
完整校验并原子启用新版后才回收旧资源；启用失败、校验失败或启用前取消保留旧版。
旧 ZIP 的迁移清理仍先确认当前完整资源可用，支持新旧两种版本目录。
当前版本、用户自建文件、外部导出与 ZIP 不误删，目录链接不跟随；清理中断后可重试，包括已删除 catalog.json 但尚未删除 revision.json 的情况。
新日期目录只是本地定位信息，不替代签名、完整清单指纹和逐个对象校验。

## 兼容范围与依据
这是电脑本地布局变更，不改 OpenWrt 19.07、21.02、22.03、23.05、24.10、25.12 的软件源、依赖范围、架构匹配、opkg/apk 参数或远端命令，因此不引入型号/驱动分支。旧 ZIP 与目录读取均有定向回归。
