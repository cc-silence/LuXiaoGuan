# 常用设置日志与反馈包

更新日期：2026-10-25。

导出入口：路由器登录页，信息窗口里的向下箭头“导出日志（始终脱敏）”。登录页与常用设置使用同一常驻后台的诊断记录。导出 ZIP 中的 `operation-diagnostics.json` 会包含常用设置记录，不仅包含当前信息窗口的文字。清空信息窗口不会清空这份结构化诊断。

## 记录内容

- 记录密码修改、LAN、主机名时区、初始安全设置、开机策略、批量身份、备份恢复、重置、重启、搬家和遗留接口清理的操作类别。
- 记录排队、执行、关键阶段、完成、取消、失败和结果未确认。任务编号 `task_id` 把一次设置和它执行的命令连起来。
- 失败包含原生错误码、异常类型、代码模块和行号，不包含异常原文或局部变量。即使 SSH 命令退出码为 0，后续配置校验失败仍会单独记录。
- 只记录结果中已明确返回的保存、应用、验证和重启状态；缺少字段时不推断“已保存”或“已应用”。保存超时、回滚未确认使用明确的不确定类别。
- 传输失败保留最后一次进度数值，不逐数据块堆积记录。显式点击确认时的输入校验失败也会记录，不记录输入框内容。

## 保留和隐私边界

- `management` 最多 128 条，`management_failures` 最多 16 条，独立于普通扫描命令记录。后续普通扫描不会直接挤掉常用设置失败记录，但新的同类记录超过上限会淘汰最旧项目。
- 结构化记录保留在本次运行内存中；请在出错后尽快导出，不要先退出软件。同一设备重连保留记录，切换到其他设备会清理旧设备记录并拒收旧任务迟到的日志。
- 不记录密码、Wi-Fi 名称、MAC、设置值、用户文件路径、原始命令或标准输出。导出时再次执行白名单与脱敏校验。
- 本次仅增加 Windows 端的诊断元数据，未增加路由器命令、软件包或硬件要求，不改变原有 OpenWrt 系统与硬件支持边界。日志能增强定位能力，但不保证仅靠日志就能确定每一种硬件故障。

## 验证

`tests/test_common_settings_diagnostics.py` 包含真实登录页导出 ZIP 的集成测试，导出前清空信息框。另验证原生错误码、输入校验、工作线程失败、关键日志保留、任务关联、切换设备隔离和私密内容不泄漏。测试用 ZIP 与验证记录位于 `build/common-settings-logging-20261025/`。

最终相关回归 131 项通过（包含 12 项日志专项测试），13 个修改或新增 Python 文件通过语法与编码检查。
