# Wireless feedback audit, 2026-10-29

The supplied archive is intact. Its device record identifies TP-Link TL-WDR7500 v3, OpenWrt 21.02.1 r16325-88151b8303, ath79/generic, ath10k_pci (5 GHz), ath9k (2.4 GHz). At capture: 120 MB total RAM, 39 MB free, 1 MB free storage. These numbers alone do not prove resource exhaustion. The log also contains a custom `diy` feed; the reported distribution/version alone does not establish byte-identical official firmware.

The AP batch reached a connected device and failed runtime verification 29 times before restoring the original configuration. Official v21.02.1 hostapd `get_status` returns status/frequency but no SSID. Our check required an SSID whenever that method existed. This exact response reproduces rejection before the fix and succeeds after it. Shared `ap_ready` now accepts an ENABLED status lacking SSID only when iwinfo on the same running interface independently reports Master mode, the same positive frequency, and the expected SSID. Explicit wrong SSID, disabled/DFS status, transport errors, wrong frequency, wrong mode, and link-down remain failures. No version/model guessing or timer is added.

Official exact source: https://raw.githubusercontent.com/openwrt/openwrt/v21.02.1/package/network/services/hostapd/src/src/ap/ubus.c . Fixed-source contracts for 19.07, 21.02, 22.03, 23.05, 24.10, and 25.12 were downloaded and SHA-256 recorded under build/feedback-1029-wireless/official-hostapd.json. This audit found that the later 21.02 contract includes SSID while exact 21.02.1 does not: series-only fixtures had missed a minor-version difference. The existing missing-method legacy path and modern exact-status path remain intact.

A second confirmed code issue: enabling boot auto-connect previously changed disabled=0 on every station carrying lxg_boot_disabled=1. This could override a later manual disable. The plan now changes only the startup policy; currently saved interface switches remain unchanged. Existing disabled stations require deliberate user activation. The boot-time suppression script and its historical signatures are unchanged. The supplied information log includes enabling this policy, but does not contain per-action before/after switches; attribution of a particular observed flip is unproven.

Orphan cleanup was exercised with eight stations alternating enabled and disabled plus historical boot markers. Wireless configuration bytes, all switch values, and runtime were preserved; no UCI apply/network reload ran. The user's reported cleanup-induced enabled-to-disabled flip is NOT reproduced or explained by this archive. The cleanup workflow is absent from the retained recent management window, and no before/after wireless values are present. The user subsequently confirmed that the enabled/disabled control itself changed, not only connection state. The newest available archive is still the 16:33:20 export above. A fresh export retaining the cleanup task is required to attribute this real configuration change; it must not be dismissed as a temporary disconnect.

Validation: 7 new regressions pass; 83 existing focused tests pass (90-case run had two new fixture failures, then fixed the offline boot command/probe mock and reran all 7 new cases successfully). No real router or local network adapter was changed. Desktop execution is common to Windows and Debian; Debian 12 runtime remains unverified. AP readiness is a device capability check rather than a CPU architecture branch. This does not establish hardware acceptance for AX3600, RT-ACRH17, AX6S, Q30 Pro, or any other model; Q30 remains distinct/unknown.
