# Initial setup and restore feedback, 2026-10-28

Common-settings messages now use InfoPanel exclusively when available, eliminating the duplicate long status banner. The existing status label remains a fallback for embedded callers without an InfoPanel. Restore completion no longer repeats the same note in a modal. Factory-reset guidance and its network recovery dialog remain intact.

InitialPolicyDialog validates selected local inputs before accept, so invalid values cannot submit a background preview. Shared initial_input_validation functions preserve the planner rules for private IPv4 /24 host addresses, SSID UTF-8 byte length/control characters, and 8-63 printable ASCII hotspot passwords. The planner still validates with the same functions; device-dependent collision, radio capability and network conflict checks remain in the background. Disabled/unselected actions do not validate unused fields. The replace-hotspot checkbox is the last configuration checkbox, followed by its conditional name/password form.

Common component: modules/common_widgets/input_validation.py exposes set_input_error(edit, invalid). It sets the inputError dynamic property and repolishes only that editor. Both settings theme partials define the red border, including settingsWindowFrame specificity; ordinary controls and layout metrics are unchanged. Editing clears the flagged state; submit revalidates. No timers, I/O, platform branches or persistent password state were added.

Qt property-selector and dynamic-style basis: https://doc.qt.io/qt-6/stylesheet-syntax.html . Tested locally with Qt 6.3.2. These are shared Python/Qt UI paths; router commands, firmware capabilities, CPU/driver selection and backup validation were not changed. Existing official OpenWrt series 19.07/21.02/22.03/23.05/24.10/25.12 boundaries remain. No new hardware-dependent path is introduced.
