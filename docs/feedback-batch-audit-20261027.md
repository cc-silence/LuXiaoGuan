# Feedback batch audit (2026-10-27)

## Result and scope

The review covered the current Windows branch changes for main-theme fallback, button focus painting, remote recursive/multi-delete, and policy recovery-copy cleanup. Three concrete defects/boundary omissions were reproduced and fixed. The final integrated suite passed 129 tests; the four separate button/style tests passed, for 133 distinct relevant checks with no skipped tests. Python compilation, Lua 5.1 compilation, UTF-8 checks and git diff --check passed.

The existing modified RouterManagerUpdater executable/metadata were present before this feedback work and were not edited or included in this source audit. No binary build, publication, real router connection or actual router deletion was performed.

## Reproduced defects and fixes

1. **Startup style conflict.** The standalone ButtonFocusStyle had an empty objectName. Real startup installed it before interaction guards, whose WidgetFilterStyle tried to recreate the current native style by that name; QStyleFactory returned no style and startup raised RuntimeError. Earlier button-only pixel checks missed this installation sequence. Focus drawing now uses the existing WidgetFilterStyle application proxy. The proxy preserves the native style key before Qt takes ownership of its base object, and invalid deleted proxy wrappers are not reused. A fresh-process test runs all four startup policy installers under Windows, WindowsVista and Fusion, verifies that the same live style remains installed, and checks the exact focus-frame primitive. Fusion can retain its normal solid focus-dependent highlight; the test does not require removing it to make focused/unfocused pixels identical. Existing input, tooltip, path-drop and interaction policies keep their shared registration/lifetime mechanism.

2. **Connection switch during a file confirmation.** Selected paths were captured before the confirmation modal loop, but submission bound the connection only after it returned. Switching the underlying connection during that wait still submitted the old targets. Expected file metadata is not a substitute for the original device binding. The shared file confirmation helper now snapshots the SSH object, transport and host fingerprint, checks them again after acceptance, and refuses submission on replacement, disconnection or changed identity. This protects the confirmation wait interval for all callers of the helper. Tests change the transport, fingerprint and connected state from inside the modal response; no delete batch is submitted.

3. **Root aliases bypassed an exact slash check.** posixpath.normpath preserves exactly two leading slashes, so // and //../ stayed distinct strings from /, while Linux resolves these rooted forms from its root directory. The common OpenWrt absolute-path normalizer now collapses leading separators before normalizing. Delete, rename and chmod root guards all operate on that canonical path and reject root aliases before opening SFTP. Normal absolute directory aliases continue to work. Tests cover multiple root spellings and both recursive deletion and the other mutation guards.

## Verification beyond method mocks

- The final 129-test suite runs after installing all shared UI policies in the same order as real startup. It covers theme/default/missing/empty fallback, file selection, confirmation, cancellation/refresh, recursive bounds, policy cleanup/rollback, original policy behavior, apply modes, official source contracts, initial-settings feedback, external drag/drop, theme/chrome rendering, tooltips, keyboard navigation and management-worker handoff.
- Four independent button/style tests cover native/themed pixels, keyboard activation, idempotence and fresh-process startup policy composition across all available native styles.
- Two tests send actual Paramiko 5.0.0 SSH/SFTP v3 packets over local socket pairs, using pinned generated test keys and an entirely in-memory file server. They cover multiple READDIR response pages, spaces/Chinese names, nested deletion, preserved external link targets, cancellation after a confirmed unlink, and closure of channels/transports/threads. No real filesystem deletion is used by these protocol fixtures.
- Real Lua 5.1 fixtures recheck policy recovery-copy cleanup, verified restoration, uncertainty retention, task ownership, extra-file/link rejection, cleanup failure/lost replies and 25 successive successful file operations without retained new task directories.
- Updated main-window dark/login and light/file-page renders were visually inspected. The sidebar and trash icons render normally; the light file view shows the themed horizontal scrollbar. These are offscreen/local renders, not the affected Win11 display.

Remaining explicit operating boundaries: remote recursive deletion is irreversible and can partially complete before cancellation/error; inventory limits are 10000 entries per selected tree, 64 levels and a 120-second task deadline with bounded channel waits. Paths passing through symbolic-link ancestors are refused; users must enter the actual directory path. Standard SFTP metadata checks cannot make pathname operations atomic against arbitrary concurrent root-level filesystem replacement. Cleanup touches only a newly owned task directory after verified success/restoration, preserves unresolved/legacy copies, and reports cleanup uncertainty; exceptional or power-loss remnants can still require review. These are not presented as live-device guarantees.
