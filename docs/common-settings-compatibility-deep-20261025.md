# 常用设置深入兼容性核查（2026-10-25）

更正：前一份“三轮”结果指三组定向回归与源码契约复核，不是三轮独立、完整的全平台兼容性验收。本次补充核查又发现三处问题，下述三处问题已按用户授权修复，下文保留修复前的证据。未向真实路由器写入。

## 已确认的遗漏

1. **P1：关闭上级开机连接时，漏检 LAN 禁用状态。** 六系列指定的 netifd 源码都会跳过 `disabled=1` 的网络接口。软件快照只包含 `auto`，没有读取 `disabled`，导致已禁用的 LAN 仍可被当成重启后的可用管理入口。新旧网桥快照均已离线复现。不是所有用户必然断联，但有丢失管理入口风险。
2. **P2：旧防火墙区域名称长度兼容缺口。** 19.07 指定的 firewall3 上限为 14，21.02 指定的上限为 11。软件允许最长 32，且没有区分当前防火墙引擎。已复现 13 字符 `uplink_custom` 被接受并生成规则；21.02 的 firewall3 会忽略超长区域，配置保存成功不能证明防护已生效。这个超长区域本身已是无效的旧配置，软件应识别并拒绝宣称兼容。不把该上限套用到 firewall4。
3. **P2：IPv6 路由会阻止初始设置修改 IPv4 登录地址。** netifd 的运行路由数组同时包含 IPv4 和 IPv6。软件把非默认 IPv6 路由也交给 IPv4 解析器，例如 `2001:db8:1234::/64` 会报格式错误。新旧网桥样本均已复现；失败发生在预览阶段，没有执行写入。

## 硬件风险（不等同于已确认真机故障）

批量更换自建 Wi-Fi 地址目前检查单播地址和重复值，没有按无线硬件的地址变化范围生成，也不在重启后核实实际广播地址。Linux 官方文档明确说明，使用地址掩码限制的硬件可拒绝启动不符合要求的接口。因此不能宣称所有芯片都能任意随机地址；未经真机证据不能指定某型号必然失败。

| 网页、SSH、校时、日志、挂载策略 | 依据前次下载的六系列服务脚本和本次固定组件源码核对；具体服务不存在时不能强行当作可用。 |
| 备份恢复 | 本次联网核对六系列 sysupgrade 的备份恢复参数；不代表备份可跨型号、跨固件恢复。 |

## 修复验证

- LAN：公共快照返回 disabled，关闭上级开机连接前检查 LAN 是否禁用。不暗中启用 LAN，开启上级连接不受该限制。
- 防火墙：同时核对已安装的标准工具和服务脚本中的引擎入口。fw3 按已核实的系列限制检查（19.07 为 14，其他支持系列为 11）；fw4 保留原有 32 字符校验，不套用 fw3 上限。引擎不明或冲突时停止并说明原因。引擎检测结果参与预览签名，改变后旧预览失效。
- 路由：按实际地址族解析，IPv4 冲突检查不再混入 IPv6；默认路由不作为地址冲突，非法地址或前缀仍明确拒绝。
- 日志：已测试真实预览校验失败经公共日志包装后留下操作、错误类别和代码位置，不保留网络名称和路由值。

相关回归 117 项通过，其中新增专项测试 9 项。另用真实 Shell 核对三份官方服务脚本的引擎识别。修复不依赖 CPU 型号，未增加路由器二进制依赖。记录位于 `build/common-settings-compatibility-fix-20261025/verification.json`。仍未执行真机写入，无线 MAC 硬件约束仍为独立待验证风险。
