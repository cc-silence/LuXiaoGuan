## 9. Offline dependency proxy fallback

No new fallback path was necessary. Both common and capture bundle services use the shared downloader. It tries configured HTTP, SOCKS and system proxy routes, then direct for transport/proxy failures and retryable gateway responses. Direct requests disable inherited requests-session proxy discovery. Manifest and archive use the same policy. Non-retryable HTTP denial, user cancellation and invalid signatures remain failures; they are not silently bypassed.

The new integration test supplies a failing proxy for both manifest and archive, verifies direct succeeds for both bundle types, and still runs actual Ed25519 signature/content verification with an isolated fixture signing key. Local package installation itself uses the downloaded package and SSH/SFTP; it does not need an application HTTP proxy.

No live user configuration file was rewritten.
