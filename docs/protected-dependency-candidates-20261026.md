# KWrt 与 SNAPSHOT 的受保护候选安装（2026-10-26）

## 用户授权与范围
用户明确要求不再仅因 KWrt 身份或带系列号的 SNAPSHOT 就直接放弃，允许先安全尝试，不合适再跳过，优先保护路由器系统；同时删除“卸载抓包依赖”总按钮。
此次授权仅开放 KWrt 的受限候选尝试，不把所有衍生固件自动纳入支持。官方离线仓库仍保留原来的严格身份匹配；兼容尝试另经公共 candidate_policy 与候选选择检查，不篡改设备身份、离线签名或支持清单。

## 行为
1. 本地仓库可对 KWrt opkg 设备选择候选。版本明确为某系列 SNAPSHOT 时，只查同系列、同 target/subtarget、同软件包架构、同包管理器的官方已签名资源；稳定版 KWrt 只查精确小版本。其他衍生固件、裸 SNAPSHOT、错误架构、平台或包格式仍不猜测。
2. 读取设备真实已装版本，计算依赖闭包；不能替换已有软件。KWrt 候选仅允许补独立工具：wpa-cli、iw、iwinfo、aircrack-ng、hcxdumptool、reaver、tmux、openssh-sftp-server。需要额外基础库、Lua/LuCI等共享组件的候选先跳过，不为装工具替换或引入核心系统组件。原有官方稳定版本匹配路径保持原策略。
3. 官方 SNAPSHOT 候选沿用已装版本比较与基础组件保护，并阻止新装内核模块、无线认证服务、网络服务等关键组件。不因此升级已有基础库。
4. 带明确系列号的 SNAPSHOT 电脑代下载使用对应系列的官方分支目录；不再一律拒绝。支持识别19.07、21.02、22.03、23.05、24.10、25.12系列，实际索引不存在或无法取得时诚实报错；识别格式不等于这些目录或每种硬件组合一定可用。24.10-SNAPSHOT/aarch64_cortex-a53/base目录本轮实际查证存在。
5. 所有按钮继续进入现有统一流程：本地资源 → 路由器自身在线软件源 → 电脑下载转装。电脑候选下载前应用相同保护，再按原规则校验哈希、IPK元数据、空间以及无联网的opkg安装预演。未放宽TLS、签名、哈希、已有包版本或原生预演要求，未添加force参数，未改固件软件源。
6. 本地候选的依赖或预演不通过，且尚未执行安装时，记录原因并转下一来源。预演原文仍以有界脱敏信息保留在信息面板/反馈日志。取消、连接中断、元数据签名/哈希损坏不降格为可重试；真正开始安装后的失败也直接停止，不盲目执行另一轮安装。
7. 删除抓包分组底部的卸载总按钮和对应状态维护，保留每行的单项安装、卸载及停止操作。后台原卸载能力保留兼容，不新增卸载流程。

## 架构与资源
candidate_policy.py集中候选安全约束，snapshot_bundle.py选择受限候选，公共下载器复用该约束。信号依赖和无线设置既有入口传入真实distribution，不另造下载实现。
无新增界面启动IO、计时器、线程或常驻缓存；候选筛选仍在现有后台任务中执行，最多遍历已验证catalog范围，取消与安装临时目录清理由原公共层负责。Windows与Debian12共用纯Python策略与既有传输层，无新平台专属导入。

## 验证
- 本轮新增候选测试17项；另增加卸载总按钮移除检查。此前“其他衍生固件不尝试”的样例从Kwrt改为ImmortalWrt，新增Kwrt正例和保护反例，未删除安全检查。
- 最终相关回归177项通过，68.162秒，进程退出码0。覆盖真实签名仓库、KWrt精确稳定版与系列SNAPSHOT、架构/平台/版本不符、已装版本不满足、基础组件保护、签名对象损坏、哈希下载、取消、原生预演拒绝、未提交时来源回退、已安装阶段失败不得换线路，以及原有分组与安全卸载流程。
- 最初定向41项中有1项测试错误地期待取消抛InterruptedError，实际原接口约定是RuntimeError。修正测试为既有约定后完成最终177项回归，未为测试改取消行为。
- 真实软件窗口内离屏绘制明暗主题、100%/150%/200%共6张图；确认总按钮已移除、单项按钮保留、按钮无越界，人工查看light-150与dark-200。截图位于build/review/protected-candidates。第一次绘图脚本找错页面属性，已纠正为登录子页后全部成功，正常退出清理。
- 修改后Python语法、UTF-8、乱码扫描与git diff --check通过。
- 未操作用户路由器，未重新打包发布，未修改离线依赖资源。用户这台2025年KWrt能否实际安装并运行wpa-cli仍需用新源码/后续打包版本验证，不能据离线测试声称已解决设备问题。

此次保护针对用户空间独立工具，拒绝内核模块，因而不新增无线芯片或驱动分支。平台和架构以设备真实字段及原生包管理器为准，不能把AX6000这次反馈推广为AX3600、RT-ACRH17、AX6S、Q30 Pro或其他型号真机通过；JCG Q30仍与Q30 Pro区分。官方精确离线包覆盖仍以support.json为准，25.12的apk路径未被当作IPK放行。
当前仅有Windows本机验证；Debian12 x86-64实际依赖、导入启动和相关功能仍待实机验收。预演和依赖声明检查不能证明所有二进制运行时ABI兼容，更不能保证安装绝无风险，所以限制为独立工具且保留运行后复测，不对未知共享组件强装。
