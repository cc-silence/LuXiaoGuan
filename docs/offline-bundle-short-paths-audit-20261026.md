# 短目录与旧包清理代码复核（2026-10-26）

## 结论
复现并修复3处边界问题。未改界面、路由器命令、依赖范围、网络线路或签名规则，未打包发布，未删除用户实际离线资源。

### 1. 损坏旧清单误报新版下载失败
复现：旧目录 catalog.json 的 profile.target 变成数字；新版已完整校验并原子切换 current.json，随后旧清理的结构校验抛出 AttributeError，导致整个下载被报失败。
修复：公共清单验证统一把结构缺字段、类型错误转换为可恢复的数据错误；旧清理保留损坏目录并警告，新版保持成功。
验证：两类离线资源均覆盖；补充不同嵌套字段损坏测试。

### 2. 只读或不存在的资源目录阻断安装回退
复现：本地没有离线资源，但安装前的锁先在资源目录 mkdir/写文件；目录不可写时，尚未判断资源不存在就抛出环境错误，挡住在线安装回退。旧只读离线资源也可能因此无法读取。
修复：锁移至现有用户配置目录下的 offline-storage-locks，以资源根的规范化绝对路径生成固定身份。同一用户下的下载、安装、提取和状态检查仍共享同一非阻塞锁；不再为读资源而创建资源目录或写入锁文件。每个资源根对应一个固定的小锁文件，不按下载版本增长。用户目录由现有 user_config_dir() 接口解析。
验证：缺失资源返回 False 交给原在线流程；旧格式资源在模拟拒绝资源目录写入时仍可检测、提取清单及安装；跨线程/跨进程占用、嵌套重入及进程异常退出释放通过。

### 3. 未完成的重复副本挡住完整资源
复现：同一完整指纹同时有完整日期目录和未完成的较早日期目录，或有空的旧64位目录。原逻辑优先选后者，误报资源缺失。
修复：存在多个同身份候选时，用已验签清单的容量和完整清单指纹选择有效候选；安装读取、准备重试、当前 ZIP 清理及旧版本回收同步使用该选择规则。只有多个候选时增加清单指纹检查，不扫描对象内容作为版本定位。
验证：旧64位副本、日期副本两种情形均覆盖，确认重试不误删完整当前目录。此定位检查不代替随后逐对象的完整性校验。

## 验证结果
Windows / Python 3.10.11：11个相关测试模块共90项通过（28.429秒），包括本次新增5项测试方法及多个格式/类型分支。Python语法、UTF-8与乱码扫描、git diff --check通过。
全部回收和故障复现均在临时目录中进行；用户配置目录也在测试中重定向到临时目录，不写入真实用户配置。
相关模块：test_bundle_storage_audit、test_bundle_layout、test_bundle_version_cleanup、test_bundle_archive_cleanup、test_common_offline_bundle、test_bundle_updates、test_bundle_export、test_bundle_export_audit、test_bundle_export_ui、test_offline_cleanup、test_package_install_guards。

## 兼容边界
本次仍仅涉及电脑本地目录、锁和清单解析，不改变 OpenWrt 19.07至25.12的系统/架构匹配、opkg/apk参数或远端行为。新旧目录及两类包覆盖，保留原有 opkg/apk 本地回归；没有据此宣称各版本/型号真机验收通过。
用户目录复用现有跨平台接口，平台文件锁延迟加载。Debian 12实际运行、锁竞争和退出清理尚无实机验证，不宣称双平台验收完成。
旧版未升级程序仍不能读取新日期目录，本次兼容方向不变：新版读取旧包、清理新旧资源。
