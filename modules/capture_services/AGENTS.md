# OpenWrt 路由器专项规则

### 当前架构方向

依赖方向固定为：

```text
主窗口/页面层
    ↓
CaptureService / OpenWrt 业务层
    ↓
OpenWrt 子服务
    ↓
平台工具、Paramiko、文件系统
```

页面层只负责控件、用户输入、确认弹窗和状态展示；服务层只负责任务编排和结构化结果；
平台/传输层负责 SSH、SFTP、远程命令和本地文件。服务层和平台层禁止反向 import 页面。

### 常驻服务和页面生命周期

- `RouterRuntime` 持有 `CaptureService`，页面只订阅服务快照。
- OpenWrt 抓包、扫描、安装或恢复任务运行时，必须通过 `activityChanged` 阻止主窗口释放。
- 页面空闲释放不能停止远端任务；页面重建后必须重新回放设备、AP、任务和结果状态。
- 应用退出必须按“停止远端进程 → 清理 monitor/临时配置 → 同步结果 → 关闭 SSH”的顺序处理。
- 任何任务都必须有超时、取消、异常捕获和最终清理；禁止在主线程同步等待远程任务。

### 不得照搬的 MintToolBox 缺陷

- 不删除 `wireless.default_radio*`，不删除不属于本任务的 monitor 接口。
- 不使用 `killall hcxdumptool`、`killall reaver`；只能按本任务登记的远端 PID 停止。
- 不使用固定 `.bak` 覆盖用户备份；备份必须唯一、成功后才能进行破坏性配置修改。
- 不修改后永久保留 HTTP 软件源，不绕过 HTTPS 校验。
- 不在 Windows 侧关闭防火墙来“解决”同步问题。
- 不使用 Paramiko `AutoAddPolicy` 无条件接受未知主机；首次指纹必须由主线程确认；已保存指纹变化时先阻止连接，再弹新旧指纹对比，用户确认后可替换重连（同地址换设备/重装不断死锁）。
- 不把工作线程中的异常吞掉后当作正常结束；错误必须结构化返回并显示建议。
- 不在主线程执行 `pool.wait()`、`sleep()`、SSH 清理或远端命令。
- 不使用 `QThread.terminate()`作为普通停止方式。
- 不让工作线程创建弹窗；所有确认、覆盖、主动断连、路由器配置修改确认均提前在主线程完成。
- 不把 SSID 直接作为 Windows 文件名；必须处理非法字符、保留名、空 SSID、重名和长度限制。
- 不把旧 HCCAPX 当主格式；原始 PCAPNG 必须可保留，22000 转换失败也要保留原始证据。
- “自动打开目录”、刷新间隔、超时、功能开关等 UI 选项必须在配置、界面和执行器三处一致生效。

## 设备操作和验证边界

- 仅操作已授权设备。radio/phy/频段必须按实机探测和当前接口归属解析，不按型号、编号猜测；歧义时阻止接管并要求刷新。
- 不提供示例设备数据代替正式结果。包管理器、架构、驱动、空间和工具能力以实机为准，不按旧记录保证支持。
- 长 SSH 脚本用 stdin 传输，避免 Dropbear 命令长度限制；远端 POSIX 路径和 Windows 本地路径分开，命令参数安全引用。
- 密码只进当前内存或 RouterManager 的 Windows 凭据管理器，不进普通配置和日志。隐私掩码不改真实任务目标。
- 安装依赖先确认清单和真实缺项，不暗中替换或升级无关包；下载核对来源和哈希，不关闭 TLS 校验。
- 无线配置变更有确认、备份和回滚；失败或取消核实恢复，未确认恢复必须明说。不操作其他任务的接口、PID 或工作目录。
- Qt 工作线程结束后通过公共任务交接机制发布最终结果，不在旧 worker 未结束时复用任务槽；不用 timer 延时掩盖生命周期错误。
- 先做定向离线回归；真机结论需有对应设备证据。不把原 WinBox 的历史通过数或待办当作独立版当前验收状态。
